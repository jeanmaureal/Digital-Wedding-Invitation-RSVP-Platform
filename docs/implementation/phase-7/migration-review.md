## 2. Security, Concurrency & Postgres Best-Practices Checklist (`TG1-C` — Gate 5)

| Check                                                                 |  Status  | Verification Notes                                                                                                                                                                                                                                                                                                                                                                                            |
| :-------------------------------------------------------------------- | :------: | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Strict Composite Foreign-Key Hierarchy (`docs/database-design.md` §1) | Reviewed | `rsvp_questions` binds `(workspace_id, wedding_id)`; `rsvp_submissions` binds `(workspace_id, wedding_id, group_id)` + `UNIQUE (group_id)`; `rsvp_attendees` binds both `(workspace_id, wedding_id, group_id, submission_id)` and `(workspace_id, wedding_id, group_id, guest_id)`; `rsvp_answers` binds `(workspace_id, wedding_id, group_id, submission_id)` and `(workspace_id, wedding_id, question_id)`. |
| Exact Leading-Column FK Indexes (`0001` & `0009`)                     | Reviewed | Every composite FK and `invitation_id -> invitations(id)` FK has an exact leading-column B-tree index with zero duplicate prefix indexes.                                                                                                                                                                                                                                                                     |
| Deadlock-Free Row-Lock Ordering (`Gate 5`)                            | Reviewed | `issue_household_invitation`, `revoke_household_invitation`, and `submit_household_rsvp` all acquire `FOR UPDATE` on `public.guest_groups` **before** locking `public.invitations` or `public.rsvp_submissions`, eliminating AB-BA deadlocks while serializing concurrent submissions and revocations.                                                                                                        |
| Single-Transaction Atomic Validation & Rollback (`Gate 5`)            | Reviewed | `submit_household_rsvp` verifies SHA-256 token hash, `status = 'active'`, `expires_at`, `'published'` wedding + active snapshot, `is_rsvp_open`, `rsvp_deadline > now()`, exact household membership, `attending_count <= max_attendees`, and custom question rules inside one transaction.                                                                                                                   |
| RLS & Explicit Role Grants (`0` `anon` table grants)                  | Reviewed | `anon` holds `0` privileges across all 4 `rsvp_*` tables; `authenticated` holds `editor`+ CRUD on `rsvp_questions` and workspace-scoped `SELECT`-only access on `rsvp_submissions`, `rsvp_attendees`, and `rsvp_answers`.                                                                                                                                                                                     |
| Non-Echoing Token Handling & Payload Safety                           | Reviewed | Neither `resolve_invitation_by_token` nor `submit_household_rsvp` ever echoes `p_token`; self-contained `app_private` triggers reject `<script`, `javascript:`, `vbscript:`, and `data:text/html` payloads (`22023 UNSAFE_RSVP_PAYLOAD`).                                                                                                                                                                     |
